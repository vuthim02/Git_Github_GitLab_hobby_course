# Day 13 Reflections: Branching Workflows

## What I Learned Today

### Workflow Summary

| Workflow | Best For | Complexity |
|----------|----------|------------|
| GitHub Flow | Web apps, CD | Low |
| GitFlow | Releases, versions | High |
| Trunk-Based | Fast teams | Low |

### Branch Types

```
main      - Production
develop   - Integration (GitFlow)
feature/* - New features
bugfix/*  - Bug fixes
hotfix/*  - Urgent fixes
release/* - Release prep
```

### Key Insight

> "The best workflow is the one your team actually uses. Start simple and add complexity only when needed."

### Naming Convention

`type/description` - Keep it readable and searchable

### When to Choose

- **GitHub Flow**: Web apps, small teams, continuous deployment
- **GitFlow**: Products with versions, scheduled releases, larger teams
- **Trunk-Based**: Fast-moving teams, CI/CD maturity
